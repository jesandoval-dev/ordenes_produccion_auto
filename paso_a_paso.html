Documento 3 · Paso a Paso Detallado — ejecutado en Sandbox

Instalación, pruebas e incidencias resueltas en Sandbox

Bitácora granular de lo que se hizo realmente en el ambiente Sandbox (3872541-sb1): despliegue de scripts, creación de accesos, corridas reales de prueba con sus datos, y las incidencias técnicas que aparecieron y cómo se resolvieron.

Contexto de la ejecución

  • Ambiente: Sandbox de Opportunity International Nicaragua (3872541-sb1.app.netsuite.com).
  • Rol de instalación: OI Gerencia Finanzas Producción (administrador).
  • Rol de prueba: Coordinador de Producción (basado en Centro clásico).
  • Resultado: instalación completa, dos corridas de proceso exitosas (lote único y lotes múltiples).

Parte A · Instalación

1Subir los archivos al File Cabinet

Documentos → Archivos → SuiteScripts. Se creó la carpeta OI_CargaProduccion y se subieron los 4 archivos en la misma carpeta (se referencian por ruta relativa):

  • oi_lib_produccion.js (librería)
  • oi_sl_carga_produccion.js (Suitelet)
  • oi_ue_wo_boton_carga.js (User Event)
  • oi_cs_wo_boton_carga.js (Client Script)
Regla crítica: si los 4 archivos no quedan juntos en la misma carpeta, la referencia relativa falla y el módulo no carga.

2Crear el Script + Deployment del Suitelet

Personalización → Scripting → Scripts → Nuevo → seleccionar oi_sl_carga_produccion.js → Crear registro de script (NetSuite detecta el tipo Suitelet).

  • Nombre: OI - Carga de Producción (Suitelet) · ID: customscript_oi_sl_carga_prod
  • Deployment ID: customdeploy_oi_sl_carga_prod
  • Se obtuvo la URL interna del Suitelet: /app/site/hosting/scriptlet.nl?script=1907&deploy=1

3Crear el Script + Deployment del User Event

Mismo camino, seleccionando oi_ue_wo_boton_carga.js (tipo User Event).

  • Nombre: OI - Botón Carga de Producción (UE) · ID: customscript_oi_ue_wo_carga_btn
  • Deployment aplicado a Orden de trabajo, ID customdeploy_oi_ue_wo_carga_btn
  • El Client Script no lleva registro propio: lo carga el User Event por ruta.

4Crear el enlace de menú (acceso tipo lista)

Se creó un Vínculo de centro (Configuración → Personalización → Vínculos centrales) etiquetado "Carga de Producción" con la URL del Suitelet, y luego una Categoría del centro para colocarlo en el menú:

  • Tipo de centro: Centro clásico (el que usa el rol Coordinador de Producción — confirmado en la definición del rol).
  • Ficha central: Transacciones. Etiqueta del grupo: Producción.

Resultado: menú Transacciones → Producción → Carga de Producción, junto al listado de Órdenes de Trabajo.

5Prueba de humo

Se abrió una Orden de Trabajo existente (con "Ver"): apareció el botón Carga de Producción junto a Editar/Atrás. Al pulsarlo abrió el Suitelet y su interfaz de carga. El enlace de menú abrió la misma interfaz. Los tres scripts corriendo correctamente.

Nota de comportamiento: el botón solo aparece al ver o editar una OT existente (no al crear una nueva), y las listas nativas no llevan botón — por eso el acceso principal es el enlace de menú.

Parte B · Incidencias encontradas y resueltas

Durante las pruebas aparecieron tres incidencias técnicas, todas de "plomería" (no de lógica de negocio). Se documentan porque forman parte del aprendizaje y aplican también al pase a Producción.

Incidencia 1 · El POST llegaba como cuerpo no-JSON

Síntoma: al validar/procesar, el servidor respondía Cuerpo JSON invalido: Unexpected token _ in JSON at position 0.

Causa: NetSuite no entregaba el cuerpo crudo del POST como JSON; el diagnóstico mostró que llegaban los campos internos del formulario (_eml_nkey_=...).

Solución: la interfaz ahora envía el payload como parámetro de formulario (payload=) y el servidor lo lee de context.request.parameters.payload.

Incidencia 2 · Los botones enviaban el formulario nativo

Síntoma: al pulsar "Validar"/"Procesar", la página navegaba a una pantalla con el JSON (envío del formulario de NetSuite), en vez de ejecutar la llamada AJAX.

Causa: un <button> dentro del formulario de NetSuite, sin type="button", actúa como botón de envío.

Solución: se añadió type="button" a ambos botones y preventDefault() en sus manejadores. Resuelto de raíz.

Incidencia 3 · Parámetro incorrecto en N/query

Síntoma: la validación fallaba con SSS_INVALID_TYPE_ARG: ...options.query.

Causa: se invocaba runSuiteQL con la propiedad sqlQuery.

Solución: se corrigieron las tres llamadas para usar la propiedad correcta query.

Parte C · Corridas de prueba reales (con datos)

Validación de inventario — los tres semáforos

Se comprobó que la validación previa funciona en sus tres escenarios:

  • ROJO Lotes inexistentes: al cargar el ejemplo del 16-jul (lotes que no existen en Sandbox), todos los lotes de MP se marcaron "no existe en inventario" y el proceso quedó bloqueado.
  • ÁMBAR Faltante parcial: al reusar lotes ya consumidos, el sistema avisó el faltante y ofreció usar el disponible del ERP.
  • VERDE Stock suficiente: con lotes reales aprobados, todo salió OK y se habilitó el proceso.
